# Contributing

Thanks for considering a contribution to `sct-marimo`.

## Before You Start

Read the [product specification](spec/product.md), [roadmap](spec/roadmap.md), and [safety statement](SAFETY.md). Search existing issues and pull requests before opening a new one. Discuss non-trivial product, trust-boundary, or dependency changes before writing substantial code.

## Issues

Bug reports should include expected and actual behaviour, exact reproduction steps, environment details, and redacted logs or screenshots. Feature requests should describe the underlying problem before proposing a solution.

Never attach licensed SNOMED CT terms, patient-identifiable data, private application rows, credentials, or sensitive local paths to a public issue.

## Pull Requests

1. Create a descriptive branch from `main`.
2. Keep the pull request focused on one coherent change.
3. Run the validation commands in [agent-instructions.md](agent-instructions.md).
4. Update documentation, tests, safety evidence, and roadmap ownership when they apply.
5. Explain the change, rationale, trust implications, and evidence in the pull request description.

## Direction

The maintainer named in the README has final responsibility for scope and design decisions. Discussion and constructive disagreement are welcome.
